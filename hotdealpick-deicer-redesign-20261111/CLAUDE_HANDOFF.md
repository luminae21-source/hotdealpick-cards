# 클로드에게 전달할 작업 지침

핫딜픽 블로그·쓰레드용 성에제거제 비교 콘텐츠를 이어서 작업합니다. 먼저 README.md, data/products.json, docs/design-rules.md와 완성 PNG 4장을 읽으세요.

1. 큰 검정 배지, 과도한 빨간 테두리, 반복되는 할인 스티커로 돌아가지 마세요. 민트·청록·네이비, 명확한 글자 크기, 여백 중심의 현재 포맷을 유지하세요.
2. 캐릭터는 assets의 골든 리트리버와 삼색 고양이입니다. 붉은 스카프와 별 머리핀을 유지하고 서로 다른 장면에는 포즈도 다르게 하세요. 정확한 상품 사진으로 오해할 가상의 제품을 만들지 마세요.
3. 가격·용량·통 수는 data/products.json만 수정합니다. 임의로 실시간 확인했다고 쓰지 마세요. 현재 데이터는 사용자 첨부 시안의 2026-11-11 18:00 자료입니다.
4. 100mL당 가격은 price / (volume_ml * count) * 100 후 반올림합니다. 막대의 시작은 0, 최대는 2,500입니다. 데이터 범위가 바뀌면 최대 축과 본문도 함께 수정하세요.
5. 표지와 비교 본문 중 ‘6종’, ‘420mL × 2통 묶음 3종’ 같은 문장은 현재 데이터에 맞춰 쓴 편집 문구입니다. JSON만 다른 주제로 바꾼다고 모든 문구가 자동 업데이트되지는 않습니다. 주제를 바꿀 때 src/render.mjs의 편집 문구도 검토하세요.
6. 각 장은 1080×1350으로 독립 제작합니다. 콜라주·격자 생성 및 콜라주 절단 금지. 글자·가격은 이미지 생성으로 다시 그리지 말고 렌더러의 텍스트 레이어로 처리하세요.
7. 실제 가격을 수정했다면 src/check.mjs의 참조 기대값과 시각도 확인된 새 값에 맞춰 검토하세요. npm run build와 npm run check를 실행하고, 4장을 직접 열어 글자 겹침·잘림·앞발 모양을 확인하세요.
8. 제휴 안내는 정확히 유지합니다. 판매처·정가·할인율·최저가 표현·검증되지 않은 효능·사용 경험을 추가하지 마세요.
9. 실제 게시 요청이 오기 전에는 블로그·쓰레드·인스타에 자동 게시하지 마세요. GitHub 변경 시 기존 프로젝트 파일을 덮지 않고 이 폴더 안에서 수정하세요.

첫 요청 예시:

“첨부한 핫딜픽 작업 파일을 읽고 이 디자인을 유지해 줘. 먼저 4장의 구성과 가격 계산을 확인한 뒤, 내가 전달하는 최신 가격만 반영해 줘. 수정한 JSON, PNG 4장, 본문 초안을 함께 제공해 줘.”
